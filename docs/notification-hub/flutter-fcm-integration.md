# Flutter — Firebase Cloud Messaging integration

[← Notification Hub overview](./README.md)

The Flutter app receives Notification Hub pushes exclusively through **Firebase Cloud Messaging** — it
never opens a SignalR connection (that's the Angular portals' transport only; see the architecture
diagram in the overview doc). Notification **history** (read/unread, past notifications) is still
available to Flutter the same way it's available to Angular: `GET /api/app/user-notifications` and
friends, the same REST endpoints the web bell dropdown uses — FCM only covers the "deliver a push while
the app may not be running" half of the picture.

There is no Flutter project checked into this repository yet; this doc + the snippets below are the
reference implementation to drop into one when it exists. The one piece that already exists and is
**reused as-is, not duplicated**, is the device-token registration endpoint
(`Eksabli.Application/Devices/DeviceAppService.cs`, `POST /api/app/devices`) — it was already built for
the campaign push channel and needs no changes for the Notification Hub.

## 1. Firebase project setup

1. Create/open the Firebase project, add an Android app (package name) and an iOS app (bundle ID).
2. Download `google-services.json` (Android) into `android/app/`, and `GoogleService-Info.plist` (iOS)
   into `ios/Runner/` via Xcode.
3. Generate a **service account** key (Project Settings → Service Accounts → Generate new private key) —
   this is the file the *backend* needs for `Fcm:CredentialsFilePath` (see the overview doc's
   Configuration section). It is not used by the Flutter app itself.

## 2. Dependencies

```yaml
# pubspec.yaml
dependencies:
  firebase_core: ^3.6.0
  firebase_messaging: ^15.1.3
  flutter_local_notifications: ^18.0.1 # foreground display — FCM alone doesn't show a
                                        # heads-up notification while the app is in the foreground
```

## 3. App bootstrap

The background message handler **must** be a top-level (or static) function — Dart isolates can't call
an instance method.

```dart
// lib/main.dart
import 'package:firebase_core/firebase_core.dart';
import 'package:firebase_messaging/firebase_messaging.dart';
import 'package:flutter/material.dart';
import 'firebase_options.dart'; // generated by `flutterfire configure`
import 'push_notification_service.dart';

@pragma('vm:entry-point')
Future<void> firebaseMessagingBackgroundHandler(RemoteMessage message) async {
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
  // Nothing else to do here for a data-only notification — the OS already shows the
  // system tray notification for messages with a `notification` payload (which is what
  // FirebaseCloudMessagingSender.SendAsync sends). Handle app-specific bookkeeping
  // (e.g. local unread-count cache) here if/when needed.
}

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
  FirebaseMessaging.onBackgroundMessage(firebaseMessagingBackgroundHandler);

  runApp(const EksabliApp());
}
```

## 4. `PushNotificationService`

Call `PushNotificationService.initialize()` once, right after login succeeds (device registration needs
an authenticated user — `POST /api/app/devices` is `[Authorize]`).

```dart
// lib/push_notification_service.dart
import 'dart:io' show Platform;
import 'package:firebase_messaging/firebase_messaging.dart';
import 'package:flutter_local_notifications/flutter_local_notifications.dart';
import 'api_client.dart'; // your existing authenticated Dio/http wrapper

/// Mirrors Eksabli.Devices.DevicePlatform (Eksabli.Domain.Shared/Devices/DevicePlatform.cs) —
/// keep these two enums in sync if the backend one ever changes.
enum DevicePlatform { iOS, android, web }

class PushNotificationService {
  PushNotificationService._();
  static final _messaging = FirebaseMessaging.instance;
  static final _localNotifications = FlutterLocalNotificationsPlugin();

  /// Requests permission, registers the current FCM token with the backend, and wires up the
  /// foreground/tap listeners. Call once after login.
  static Future<void> initialize(ApiClient apiClient) async {
    await _messaging.requestPermission(alert: true, badge: true, sound: true);

    await _initLocalNotifications();

    final token = await _messaging.getToken();
    if (token != null) {
      await _registerDevice(apiClient, token);
    }

    // Token rotates (app reinstall, OS-level refresh, ...) — re-register whenever it does.
    _messaging.onTokenRefresh.listen((newToken) => _registerDevice(apiClient, newToken));

    // App in the foreground: FCM does NOT show a system notification automatically — show one
    // ourselves via flutter_local_notifications so foreground behavior matches background.
    FirebaseMessaging.onMessage.listen(_showLocalNotification);

    // User tapped a notification (from background/terminated) — route using the same
    // Category/Data payload UserNotificationDto carries on the web side (see
    // FirebaseCloudMessagingSender.cs — Data['title']/['body'] are additive extras today, the
    // Notification field is the human-visible part on both platforms).
    FirebaseMessaging.onMessageOpenedApp.listen(_handleNotificationTap);
  }

  static Future<void> _registerDevice(ApiClient apiClient, String pushToken) async {
    await apiClient.post('/api/app/devices', data: {
      'platform': _currentPlatform().index,
      'pushToken': pushToken,
      'appVersion': await _appVersion(),
    });
  }

  static DevicePlatform _currentPlatform() {
    if (Platform.isIOS) return DevicePlatform.iOS;
    if (Platform.isAndroid) return DevicePlatform.android;
    return DevicePlatform.web;
  }

  static Future<String?> _appVersion() async => null; // wire up package_info_plus if desired

  static Future<void> _initLocalNotifications() async {
    const androidInit = AndroidInitializationSettings('@mipmap/ic_launcher');
    const iosInit = DarwinInitializationSettings();
    await _localNotifications.initialize(
      const InitializationSettings(android: androidInit, iOS: iosInit),
      onDidReceiveNotificationResponse: (response) {
        // Local (foreground-shown) notification tapped — same routing as _handleNotificationTap.
      },
    );
  }

  static Future<void> _showLocalNotification(RemoteMessage message) async {
    final notification = message.notification;
    if (notification == null) return;

    const androidDetails = AndroidNotificationDetails(
      'eksabli_notifications',
      'Eksabli notifications',
      importance: Importance.high,
      priority: Priority.high,
    );
    await _localNotifications.show(
      notification.hashCode,
      notification.title,
      notification.body,
      const NotificationDetails(android: androidDetails, iOS: DarwinNotificationDetails()),
      payload: message.data['category'] as String?,
    );
  }

  static void _handleNotificationTap(RemoteMessage message) {
    final category = message.data['category'] as String?;
    // e.g. switch (category) { case 'billing.payment_failed': ... }
    // Deep-link using whatever navigation/router the app already uses.
  }

  /// Call on logout so a shared device stops receiving this user's notifications.
  static Future<void> deregister(ApiClient apiClient, String deviceId) async {
    await apiClient.delete('/api/app/devices/$deviceId');
  }
}
```

## 5. What the backend actually sends

`FirebaseCloudMessagingSender` (`Eksabli.Domain/Notifications/FirebaseCloudMessagingSender.cs`) sends a
standard FCM `Message` with a `Notification` block (`title`/`body` — shown by the OS automatically when
the app is backgrounded/terminated) plus a small `data` block carrying the same `title`/`body` again for
convenience. `NotificationPublisher.PublishToUserAsync` is the only path that pushes via FCM today (see
the overview doc's "why two storage entities" section for why Tenant/Broadcast targets don't fan out to
FCM inline) — every registered `Device.PushToken` for that one user gets the push.

## 6. Testing without a real device

Use the `POST /api/app/user-notifications` endpoint (`Eksabli.Notifications.Broadcast` permission,
e.g. via Swagger) with `targetType: 0` (User) and your test user's id — this exercises the full
`NotificationPublisher` → `FirebaseCloudMessagingSender` path exactly as any other application event
would.
